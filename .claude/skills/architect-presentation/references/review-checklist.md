## 상세 적용

- 본문에는 중요한 FR 약 4–6개, 선택 QA 약 3–6개를 보여주는 팁을 참고한다. 이는 가이드이며 사용자 범위나 실제 요구를 삭제하는 근거가 아니다. 나머지와 선정 과정은 부록에 남긴다.
- QA 시나리오는 Source, Stimulus, Artifact, Environment, Response, Response Measure를 연결한다. 지표가 서로 다른 경우 시나리오를 나누고, 여러 수치를 한 QA 항목에 뒤섞지 않는다.
- 우선순위를 발표 편의로 조작하지 않는다. 동순위가 존재할 수 있으므로 선택·제외 이유를 설명한다.
- 대안의 효과는 기법 이름이나 별점만으로 단정하지 않는다. 문헌·분석·프로토타입·측정 근거를 제시한다. 검증되지 않은 기대효과와 실제 결과를 구분한다.
- 최종 구조에 각 DP의 선택이 어디 반영되는지 표시한다. 선택 이유가 전체 목적과 제약에 부합해야 한다.
- 성과는 처음 제시한 목표에 대응시킨다. 실제 제품 적용, 비즈니스 결과, 특허·시상·리더십 활동은 제공된 증거가 있을 때만 넣는다.
- 예상 질문별 Appendix를 준비하고 본문으로 돌아오는 링크를 연결한다. 질문 의도가 불명확하면 확인한 뒤 답변한다. 답변은 결론을 먼저 말하고 근거를 이어간다.

## 제작자가 추가한 검증 규칙

다음은 위 PDF의 직접 인용이 아니라 신뢰성 확보를 위한 운영 규칙이다.

- 별점을 쓰면 1–5점의 기준, 방향성, 측정 조건, 근거 종류를 함께 정의한다.
- 검증 상태를 실측 / 시뮬레이션 / 문헌 / 논증·추정 / 미검증으로 구분한다.
- 임의의 달성률·성능 배수·실험 결과·개인 기여를 생성하지 않는다.
- 최신 설계 문서와 슬라이드의 모듈 이름·DP 범위·용어를 맞춘다.
