# 재개 절차 (인계를 받는 쪽)

사용자가 "인계받아 재개", "RESUME.md 읽고 이어서", "사내에서 이어서 작업" 이라고 할 때 따른다.

## 1. 읽는 순서 (반드시 이 순서)

```text
doc-mk/handoff/RESUME.md          최신 세션이 어느 디렉터리인지, 인계 체인이 어떻게 되는지
        ↓
sessions/<최신>/handoff.md        ★ 현재 참인 것. 여기서 컨텍스트를 만든다
        ↓
sessions/<최신>/stats.md          커밋 로그로 저장소 상태 대조
        ↓
(필요할 때만) prompts.md          "사용자가 정확히 뭐라고 했나"를 확인해야 할 때
(마지막 수단) dialogue.md         특정 판단의 근거를 되짚어야 할 때
```

**원문(`prompts.md`/`dialogue.md`)을 먼저 읽지 마라.** 원문에는 이미 철회된 주장과
버려진 설계가 그대로 남아 있다. 문맥 없이 읽으면 그것들을 되살린다.
`handoff.md`가 현재 상태이고, 원문은 그 근거를 캘 때만 연다.

## 2. 첫 턴에 할 확인 (한 번만)

`handoff.md`의 "확정 사실"은 다른 환경에서 쓰인 것이다. 그중 **이 저장소 안에서
확인 가능한 것만** 실제로 확인한다. 확인 못 하는 것(외부 실측, 웹 근거)은
`[미검증]` 그대로 두고 진행한다.

```bash
git log --oneline -10                       # handoff.md의 커밋과 일치하나
<재현 명령 그대로 실행>                       # 테스트가 실제로 통과하나
grep -n "<확정 사실이 가리키는 심볼>" <경로>   # 코드 위치가 아직 유효한가
```

어긋나면 **먼저 사용자에게 알린다.** 인계 문서가 저장소보다 오래된 상태일 수 있다.

## 3. 지켜야 할 제약

| 제약 | 이유 |
|---|---|
| 기각 이력의 안을 다시 제안하지 않는다 | 이미 반박된 안이다. 뒤집으려면 기각 이유가 무효가 된 근거를 먼저 댄다 |
| 정정 이력에서 취소선 그어진 주장을 쓰지 않는다 | 사용자가 직접 틀렸다고 한 문장이다 |
| 용어 절의 정의를 바꾸지 않는다 | 같은 단어가 두 뜻으로 돌면 논의가 어긋난다. 바꾸려면 명시적으로 선언한다 |
| "다음 한 수"부터 시작한다 | 재개 지점이 이미 지목돼 있다. 다시 고르지 않는다 |

## 4. 재개 후 첫 응답

사용자에게 이렇게 보고한다 — 길게 요약하지 말고:

```text
인계 확인: <세션명> (<기간>, 커밋 <해시>)
저장소 대조: <일치 / 어긋난 항목>
다음 한 수: <handoff.md 8절 그대로>
진행할까요, 아니면 다른 것부터?
```

인계 내용을 통째로 재요약해서 되돌려주지 마라. 사용자는 이미 그 작업을 한 사람이다.
