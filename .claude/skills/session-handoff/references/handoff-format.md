# `handoff.md` 작성 규칙

원문(`prompts.md` / `dialogue.md`)이 있는데도 이 문서를 따로 쓰는 이유는 하나다.
**원문은 무엇이 있었는지를 말하고, 이 문서는 지금 무엇이 참인지를 말한다.**
원문에는 이미 철회된 주장, 중간에 틀린 계산, 버려진 설계가 그대로 남아 있다.
재개하는 세션이 원문을 먼저 읽으면 그 폐기물을 되살린다. 그래서 순서가 중요하다:
**handoff.md가 먼저, 원문은 근거 확인용.**

## 절 구성

아래 8개 절을 이 순서로 쓴다. 빈 절은 지우지 말고 `없음`이라고 적는다 —
"기각한 대안이 없음"과 "기각 절을 안 씀"은 재개하는 쪽에서 구별되지 않는다.

---

### 1. 한 문단 요약

지금 무엇을 하는 작업이고, 어디까지 왔는지. **5줄 이내.**
목표(왜 하는가)와 현재 위치(어디까지 됐는가)를 각각 한 문장 이상 담는다.

### 2. 확정 사실

재개하는 세션이 **다시 조사하지 않아도 되는 것**. 각 항목에 근거를 붙인다.

```markdown
| 사실 | 근거 | 검증 |
|---|---|---|
| `bind_gpu_block_pool`은 `KVConnector` ABC에 없다 | `vllm/.../v1/base.py` grep 0건 | 확인함 |
| 70B GQA KV = 320 KB/token | 80층×8헤드×128×2×2B 자체 계산 | 계산 |
| 출력 길이 예측 정확도 | — | **[미검증]** |
```

- 근거는 **파일 경로·줄 번호·명령어·계산식** 중 하나여야 한다. "논의에서 합의됨"은 근거가 아니다.
- 검증 안 된 것은 반드시 `[미검증]`. 사내 세션은 저장소 밖을 못 볼 수 있으므로,
  여기 적힌 것이 사실상 유일한 근거가 된다.

### 3. 확정된 결정

내린 결정과, **무엇을 포기하고 내렸는지**. 포기한 것이 없으면 그건 결정이 아니라 기본값이다.

```markdown
- **결정**: DP1 최종 구조 = C1 + 컨텍스트 길이 보강
  - 근거: QA 가중치상 정보비용(N→T)이 배치품질 격차보다 크다
  - 포기한 것: 객체별 등급 구분 능력
  - 뒤집히는 조건: 실측에서 오분류율 < 10% 이고 대역폭 매칭 격차 > 2배
```

### 4. 기각한 대안

**이 절이 이 문서의 가장 큰 가치다.** 재개하는 세션은 문맥이 없으므로
기각된 안을 반드시 다시 떠올린다. 기각 이유를 남겨 두면 그 턴이 통째로 절약된다.

```markdown
| 기각한 안 | 기각 이유 | 되살릴 조건 |
|---|---|---|
| 하이브리드(C1+C2 혼합)를 세 번째 후보로 | 단일 진실 원천이 여전히 하나 → 후보가 아니라 보강 | 결정 단위가 실제로 분리되면 |
| 런타임 재분류를 C2에 포함 | 결정 변수가 달라짐 → 별개 DP(DP4) | — |
```

### 5. 정정 이력

**사용자가 틀렸다고 지적한 내 주장**을 원문 그대로 남긴다. 요약하면 힘이 빠진다.

```markdown
- ~~"prefix cache hit 시 100명이 각자 등급을 묻는다"~~
  → **틀림.** hit에서는 배치 결정 자체가 일어나지 않는다. 두 후보 동작이 동일하다.
- ~~"C2의 계약은 capacity-blind다"~~
  → **과장.** C2도 tier 상태를 읽는다. 다만 아래 방향으로만 읽는다.
```

이 절은 삭제하지 않고 **누적**한다. 같은 함정에 두 번 빠지는 걸 막는 게 목적이다.

### 6. 용어

세션 안에서 정의했고 저장소 밖에서는 통하지 않는 말. 한 줄 정의.

```markdown
- **유보 A**: step 안에서만 유효한 예약. 계산으로 나오는 값, 정합성 요구.
- **유보 B**: 미래 여유분. 튜닝 파라미터, 성능 요구. 도착 분포에 의존.
- **steelman**: 각 후보를 최선의 형태로 세운 뒤 비교하는 원칙.
```

### 7. 산출물 지도

파일마다 **무엇을 담고 / 어느 상태인지**. 목록만 나열하는 건 금지.

```markdown
| 경로 | 담고 있는 것 | 상태 |
|---|---|---|
| `doc-mk/vllm-dp1-*.md` | DP1 본문 12절 | §1.3만 재작성 대기 |
| `doc-mk/prototype/` | 두 후보 구현 + 테스트 | 35/35 통과 |
| `doc-mk/ppt/*.pptx` | 덱 3종 | 문서 변경분 미반영 |
```

재현 명령을 같이 적는다:

```markdown
    cd doc-mk/prototype && python3 -m pytest tests/ -q      # 35 passed
    cd doc-mk/ppt && NODE_PATH=<...> node build-dp1-full-deck.js
```

### 8. 다음 한 수

재개하는 세션이 **첫 턴에 바로 할 일 하나**. 후보 나열이 아니라 지목이다.
그 뒤에 대기 중인 항목을 우선순위대로 붙인다.

```markdown
**다음 한 수**: `doc-mk/vllm-dp1-*.md` §1.3을 고쳐 쓴다.
현재 문장 "DIP는 지켜져 있다"를 오늘 이미 존재하는 결함 서술로 교체한다
(근거는 §2 확정 사실 3~5행). 그다음 full deck 5장 부제를 맞춘다.

대기:
1. 비교 덱(5장)·상세 덱(10장)의 대표 도면을 새 배경에 정렬
2. TESTING.md의 `--policies c1,c2-steelman` 예시 정정
3. DP3(재배치 트리거) / DP4(특성 예측) 문서화
```

---

## 분량

`handoff.md`는 **한 화면에 안 들어가야 정상이고, 스크롤 세 번을 넘기면 과하다.**
넘치면 8절 자체를 줄이는 게 아니라 2절(확정 사실)을 별도 파일로 뺀다.
줄여야 할 때 가장 먼저 버릴 것은 1절 요약이고, 마지막까지 지킬 것은 4·5·8절이다.
