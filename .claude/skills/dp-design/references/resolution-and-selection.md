# Phase 7~9 — 문제 해결 검증, 최종 구조 선택, 잔여 문제 인계

## 왜 트레이드오프 다음에 별도 단계가 필요한가

트레이드오프 평가는 **상대 비교**다 — "둘 중 어느 쪽이 어느 축에서 나은가".
문제 해결 검증은 **절대 판정**이다 — "이 후보가 애초에 풀려던 문제를 푸는가".

두 후보가 비등하다는 것이 둘 다 문제를 푼다는 뜻은 아니다. 별점이 좋아도 배경의 제약을 위반하면 탈락이고,
두 후보 모두 문제를 못 풀면 트레이드오프 표 자체가 무의미하다. 그래서 별도 관문이다.

# Phase 7. 문제 해결 검증

## 검증 재료는 전부 Phase 1에 이미 있다

Phase 1에서 쓴 네 가지를 그대로 체크리스트로 되돌린다.

| Phase 1의 산출물 | Phase 7에서 묻는 것 |
|---|---|
| 문제 한 문장 | 이 후보에서 그 문장이 더 이상 참이 아닌가? |
| QA 영향 수치 | 그 수치가 실제로 개선되는가? (As-Is → To-Be) |
| 제약 | 위반하지 않는가? |
| 가정 / 범위 밖 | 이 후보가 배경의 가정과 어긋나거나 범위 밖을 끌어들이지 않는가? |

## 검증표 형식

```markdown
| 배경에서 정의한 것 | As-Is | Candidate 1 | Candidate 2 | 판정 |
|---|---|---|---|---|
| **문제 한 문장** | <현재 상태> | <이 후보에서의 상태> | <동일> | 해결 / 부분 / 미해결 |
| QA1 영향: <지표> | <배경 값> | <후보 값> | <후보 값> | |
| QA2 영향: <지표> | | | | |
| 제약: <제약 내용> | — | 준수 / 위반 | 준수 / 위반 | |
| 가정: <가정 내용> | — | 부합 / 어긋남 | | |
```

## 판정 4단계

| 판정 | 의미 | 후속 |
|---|---|---|
| **해결** | 문제 진술이 더 이상 참이 아니다 | — |
| **부분 해결** | 문제의 일부만 해소, 잔여가 남는다 | 잔여를 Phase 9로 **반드시** 인계 |
| **미해결** | 문제 진술이 그대로 참이다 | 이 후보는 선택 대상이 아니다 |
| **제약 위반** | 배경에 명시한 제약을 깬다 | **즉시 탈락.** 별점과 무관하다 |

## 규칙

1. **제약 위반은 트레이드오프를 이긴다.** ★★★가 세 개여도 제약을 깨면 탈락이다.
2. **두 후보 모두 미해결이면 Phase 2로 복귀한다.** 결정 변수가 문제와 어긋나 있다는 뜻이다. 후보를 다듬을 게 아니라 쟁점을 다시 잡아야 한다.
3. **부분 해결의 잔여를 조용히 넘어가지 않는다.** 잔여를 적지 않으면 그 문제는 구현 단계에서 발견된다.
4. QA 영향 수치는 **As-Is → To-Be로** 쓴다. 값이 안 바뀌면 "미해소"라고 명시한다. 좋아 보이게 쓰지 않는다.
5. 두 후보의 판정이 같아도 된다. 이 단계는 우열을 가리는 자리가 아니다.

# Phase 8. 최종 구조 선택

## 자격

Phase 7에서 **제약 위반·미해결이 아닌 후보만** 선택 대상이다.

## 별점 합계로 고르지 않는다

합계는 비등성을 확인하는 요약값이지 선택 기준이 아니다. 선택은 **QA 가중치**로 한다.
그리고 가중치는 취향이 아니라 Phase 1의 **제약과 가정**에서 도출한다.

## 선택 서술 형식

> 우리 맥락에서 **\<QA-a\>** 는 **\<QA-b\>** 보다 중요하다.
> 근거는 \<Phase 1의 제약 / 가정 / 측정값\>이다.
> 따라서 **\<후보\>** 를 최종 구조로 선택한다.
> 이 선택으로 포기하는 것은 \<진 축의 손실\>이며, 그 손실은 \<완화책 또는 수용 사유\>로 다룬다.

마지막 줄을 빼지 않는다. 무엇을 포기했는지 쓰지 않은 선택은 트레이드오프를 분석한 의미가 없다.

## 데이터로 가를 수 있으면 데이터로 가른다

선택을 좌우하는 값이 측정 가능하면 **PoC 항목으로 명시하고 측정 전에는 선택을 유보**한다. 세 가지를 쓴다.

| 항목 | 내용 |
|---|---|
| 측정 대상 | 무엇을 재는가 (한 문장) |
| 측정 방법 | 어떤 데이터로 어떻게 재는가 |
| 판정 임계값 | 어느 값 이상/이하면 어느 후보인가 |

임계값을 미리 못 박아야 측정 결과를 보고 해석을 바꾸는 일이 없다.

## 선택하지 않은 후보는 폐기가 아니다

**반전 조건(reversal condition)** 을 명시한다.

> \<어떤 값\>이 \<어떻게\> 바뀌면 이 선택은 뒤집힌다.

이것이 재검토 트리거가 되고, 나중에 조건이 바뀌었을 때 처음부터 다시 설계하지 않아도 된다.

# Phase 9. 잔여 문제와 DP 연결

DP가 고립되어 읽히면 가치가 떨어진다. **잔여 문제를 다음 DP로 넘기는 것이 DP 간 결합을 만든다.**
Phase 7에서 "부분 해결"이 나왔다면 이 절은 선택이 아니라 의무다.

## 잔여 문제 기술 형식 (항목마다)

```markdown
### 잔여 R<N>. <잔여 문제 한 문장>

- **왜 이 DP에서 풀 수 없는가**: <결정 변수가 다르다 / 배경에서 범위 밖으로 정의했다>
- **어디서 푸는가**: DP<M> (기존) 또는 신규 DP 제안 + 그 DP의 설계 질문 초안
- **결합 방향**: 이 DP에서 <후보>를 선택했으므로 DP<M>의 후보는 <어떻게> 제약된다
```

"왜 이 DP에서 풀 수 없는가"가 핵심이다. 이 답이 없으면 잔여 인계는 **회피**로 읽힌다.
정당한 답은 둘뿐이다: (a) 결정 변수가 다르다, (b) 배경에서 명시적으로 범위 밖으로 선언했다.

## DP 결합 맵

문서 말미에 표 하나. 이 DP가 무엇에 제약받고 무엇을 제약하는지.

| 관계 | 상대 DP | 내용 |
|---|---|---|
| **상류** (이 DP를 제약) | DP\<n\> | \<그 DP의 결정이 이 DP의 후보를 어떻게 제한했는가\> |
| **하류** (이 DP가 제약) | DP\<m\> | \<이 DP의 선택이 그 DP의 후보를 어떻게 제한하는가\> |
| **형제** (같은 축을 공유) | DP\<k\> | \<함께 봐야 하는 이유\> |

# Phase 9-B. 혼합 구조를 최종안으로 삼는 경우

## 먼저 판정한다 — 진짜 혼합인가, "한 후보 + 보강"인가

Phase 2의 결정 변수는 **인덱스 축 하나**였다. 최종안에서 그 축이 여전히 하나면 그것은 혼합이 아니다.

> **판정 질문**: 최종안에서 그 사실·정책의 **단일 진실 원천이 여전히 하나인가?**
> - 하나 → **선택된 후보 + 보강**이다. 그렇게 부르면 Phase 3의 배타성 논증이 그대로 유효하다.
> - 둘 → **진짜 혼합**이다. 아래 정당화가 필요하다.

실무 결론의 대부분은 전자다. 진 후보의 요소를 tie-breaker·가중치·폴백으로 얹는 것은 축을 바꾸지 않는다.
**정직하게 "C\<n\> 선택 + \<무엇\> 보강"으로 부르고, 보강이 진 축의 손실을 얼마나 회복하는지 수치로 쓴다.**

## 진짜 혼합이라면 — "왜 처음부터 후보가 아니었는가"에 답해야 한다

Phase 3의 합성 테스트(T1)가 "합칠 수 없다"고 논증했으므로, 혼합을 최종안으로 삼는 순간 그 논증과 충돌한다.
다음 중 하나로 해소한다. **해소하지 못하면 T1이 애초에 틀렸던 것이므로 Phase 2·3을 다시 쓴다.**

| 유형 | 내용 | 후속 조치 |
|---|---|---|
| **인식 순서** | 혼합의 필요성과 **형태**는 두 극단을 각각 끝까지 밀어 정량화한 뒤에야 드러났다. 그 전에는 "어디를 섞어야 하는가"를 특정할 수 없었으므로 후보로 세울 수 없었다 | 그대로 서술. 가장 흔하고 정직한 이유다. 어느 측정값이 그 판단을 가능하게 했는지 명시 |
| **비용 정보 확보** | 혼합이 추가로 요구하는 것(모듈·상태 동기화·일관성 관리)의 크기를 두 극단의 비용을 재기 전에는 산정할 수 없었다 | 그 비용을 수치로 제시 |
| **축 분해** | 두 후보를 그려보니 결정 변수가 하나가 아니라 둘이었음이 드러났다. 하나로 본 동안에는 배타적이었다 | **Phase 2를 다시 쓴다.** DP를 둘로 쪼갤지 함께 검토 |
| **외부 조건 변화** | 설계 도중 제약이 바뀌었다(HW 스펙 확정, 상류 DP 결정, 성능 예산 완화) | 변경 시점과 내용을 기록. 배경의 제약 절도 갱신 |

**정당화가 아닌 것**: "둘 다 좋아 보여서", "리스크를 줄이려고". 이것은 결정 회피이지 설계가 아니다.

## 혼합을 최종안으로 삼을 때 추가로 써야 할 것

- **축별 귀속**: 혼합은 평균이 아니라 **축별 선택의 조합**이다. 어느 축에서 어느 후보의 값을 취했는지 표로 쓴다.
- **회피한 단점 / 새로 생긴 단점**: 두 후보의 단점 중 무엇을 피했고, 혼합이 **새로 만드는** 단점이 무엇인가.
- **같은 QA 축으로 혼합을 재평가한 별점**. 여기서 규칙 하나:

> **혼합이 두 후보를 지배하지 못하면 혼합은 답이 아니다.**
> 혼합은 항상 복잡성 비용을 더한다. 그 비용을 내고도 모든 축에서 같거나 낫지 않다면,
> 비용만 늘고 이득이 없는 구조다 — 그때는 한 후보를 고르는 편이 낫다.

이것은 Phase 3의 지배 금지 규칙(T3)과 모순되지 않는다. T3는 **후보 사이**에 지배가 없어야 한다는 규칙이고,
여기는 **최종안이 후보들을 지배해야 한다**는 규칙이다. 방향이 반대다.
