# Phase 5 — QA 기반 3점 별점 트레이드오프

## 1. 원칙

트레이드오프는 **후보의 특징을 하나씩 열거하는 것이 아니다.**
Phase 0에서 고정한 QA 축에 두 후보를 투영해 별점을 매기고, 그 별점의 근거를 숫자로 대는 것이다.

- 축은 Phase 0의 QA와 **정확히 동일**. 추가·누락 금지.
- 별점은 **후보 간 상대 평가**다. 절대적 좋음이 아니라 "이 축에서 어느 쪽이 구조적으로 유리한가".
- 모든 셀의 근거는 `diagrams.md`의 추출표에서 온다.

## 2. 별점 기준

| 별점 | 의미 | 판정 기준 |
|---|---|---|
| ★★★ | 구조적으로 유리 | 프록시 값이 상대 후보보다 유의미하게 우수하거나, 이 QA를 위한 추가 비용이 0 |
| ★★☆ | 가능하지만 비용 발생 | 동작은 하나 추가 단계·추가 관리·우회가 필요 |
| ★☆☆ | 구조적으로 불리 | 이 축의 요구를 만족시키려면 구조 자체를 바꿔야 함 |

- 같은 QA에서 두 후보가 같은 별점이면 **변별력이 없다.** 축에서 제거하거나 더 날카롭게 재정의한다.
- 별점은 "구조가 그렇게 생겨서" 나오는 값이다. 구현 품질이나 최적화 여지로 별점을 조정하지 않는다.

## 3. 매트릭스 형식

```markdown
> ★★★ = 구조적으로 유리 / ★★☆ = 가능하나 비용 발생 / ★☆☆ = 구조적으로 불리

| QA | Candidate 1: <이름> | Candidate 2: <이름> | 정량 근거 |
|---|:---:|:---:|---|
| **<QA1>** | ★★★ | ★★☆ | C1 dispatch 3 메시지 / lookup 0회, C2 6 메시지 / lookup 2회 (시퀀스) |
| **<QA2>** | ★★☆ | ★★★ | C1 선택 가능 리소스 1개, C2 N개 (컴포넌트) |
| **<QA3>** | ★★☆ | ★★★ | C1 1:1만 표현, C2 1:N·N:M 표현 (컴포넌트) |
| **<QA4>** | ★★☆ | ★★★ | 신규 1종 추가 시 수정 클래스 C1 2개 / C2 0개 (클래스) |
| **합계** | 9 | 11 | 지배 없음, 차이 2 이내 |
```

합계는 ★을 1/2/3점으로 환산한다. 대시보드 요약용이지 우열 판정용이 아니다.

## 4. 근거 작성 규칙

각 셀 근거는 **`<숫자 비교> (<출처 다이어그램>)`** 형식 한 줄.

| 나쁨 | 좋음 |
|---|---|
| 경로가 짧아 빠르다 | dispatch까지 3 메시지 vs 6 메시지, lookup 0회 vs 2회 (시퀀스) |
| 확장에 유리하다 | 신규 백엔드 추가 시 수정 클래스 0개 vs 2개, 인터페이스 변경 0건 vs 1건 (클래스) |
| 유연하다 | 표현 가능한 관계 1:1 only vs {1:1, 1:N, N:M} (컴포넌트) |
| 관리가 복잡하다 | 유지 메타데이터 엔트리 0개 vs (memory 수 × compute 수)개 (컴포넌트) |

절대 수치를 모를 때는 **상대 비교와 증가 차수**로 쓴다: "리소스 수 n에 대해 O(1) vs O(n) 탐색".
추정치는 추정임을 밝히고 산출 근거를 남긴다: "op당 약 0.5~1 us (lookup 2회 × 해시 조회 기준 추정)".

## 5. QA별 상세 비교 절

매트릭스 다음에 QA마다 한 절을 둔다. 절 구성은 고정:

```markdown
## QA<N>. <QA 이름>

### Candidate 1 — ★★☆
<해당 후보의 경로/구조를 보여주는 축약 그림>
- 정량 사실 1 (숫자)
- 정량 사실 2 (숫자)
- 구조적 이유 1줄

### Candidate 2 — ★★★
(동일 형식)

**Trade-off:**

> **<C1이 얻는 것> ↔ <C2가 얻는 것>**
```

Trade-off 한 줄은 **대구**로 쓴다. 한쪽만 서술하면 그것은 트레이드오프가 아니라 평가다.

## 6. 검증 (Gate E 자동 점검 순서)

1. 축 = Phase 0 QA 집합인가? (집합 동일성)
2. 모든 셀에 숫자가 있는가?
3. 지배가 있는가? (한 후보가 모든 축에서 ≥) → 있으면 후보 또는 축 재설계
4. 각 후보가 ★★★을 최소 1개 갖는가?
5. 합계 차이 ≤ 2인가?
6. 같은 별점 쌍이 있는가? → 해당 축 재정의 또는 제거

3~5가 깨지면 **별점을 조정해 맞추지 말 것.** 후보 구조나 QA 축을 다시 세우는 것이 정답이다.
별점을 손대는 순간 문서는 결론을 정당화하는 문서가 된다.
