# Phase 6 — DP PPT 페이지 (한 장, 비교 표 1개)

## 1. 표 구조 (고정)

한 페이지에 큰 표 하나. 가로축 = 두 후보 구조, 세로축 = 5개 항목.

| | **Candidate 1: <이름>** | **Candidate 2: <이름>** |
|---|---|---|
| **후보 구조 이름** | <이름> — <한 문장 특징> | <이름> — <한 문장 특징> |
| **대표 구조도** | <도형 5개 이하 축약도> | <도형 5개 이하 축약도> |
| **장점** | • 3~4개 | • 3~4개 |
| **단점** | • 3~4개 | • 3~4개 |
| **TRADEOFF 관계** | <A ↔ B 대구 한 문장 — 두 칸을 병합해 한 줄로 써도 된다> | |

## 2. 셀 작성 규칙

### 후보 구조 이름
- 결정 변수의 값이 드러나는 이름 (`Memory-Coupled` / `Decoupled`).
- 한 문장 특징은 **확보 + 포기**를 함께 담는다.

### 대표 구조도
- 본문보다 **더 축약**한다: 도형 5개 이하, 세로 흐름 1줄.
- 두 칸의 그림은 **같은 시각 문법**(같은 시작 요소, 같은 방향, 같은 도형 크기).
- 텍스트는 도형당 2~3 단어.

### 장점 / 단점
- 각 3~4개, **1줄 40자 이내**.
- 각 항목은 가능하면 **QA 이름을 앞에 달아** 트레이드오프 표와 연결한다.
  예: `(Efficiency) dispatch 3 메시지, lookup 0회`
- 장점 개수와 단점 개수를 두 후보 간 맞춘다. 개수 불균형 자체가 편향 신호로 읽힌다.

### TRADEOFF 관계
- `<C1이 확보하는 것> ↔ <C2가 확보하는 것>` 대구 한 문장.
- 예: **낮은 dispatch overhead와 예측 가능성 ↔ 동적 리소스 선택과 확장성**

## 3. 작성 예 (DP2)

| | **Candidate 1: Memory-Coupled** | **Candidate 2: Decoupled** |
|---|---|---|
| **후보 구조 이름** | Memory-Coupled — 메모리가 연산 능력까지 소유해 짧은 실행 경로를 얻는 대신 유연성을 포기 | Decoupled — 메모리와 연산을 분리해 유연성을 얻는 대신 계획 오버헤드를 감수 |
| **대표 구조도** | `Request → Memory(연산 포함) → Execute` | `Request → Memory → Binding → Planner → Execute` |
| **장점** | • (Efficiency) dispatch 3 메시지, lookup 0회<br>• (Predictability) 런타임 분기 0개<br>• 구현 단순: 신규 컴포넌트 0개 | • (Utilization) 선택 가능 리소스 N개<br>• (Flexibility) 1:N·N:M 표현 가능<br>• (Extensibility) 신규 추가 시 수정 클래스 0개 |
| **단점** | • (Flexibility) 1:1 관계만 표현<br>• (Extensibility) op 추가 시 인터페이스 확장<br>• 메모리 추상화 책임 비대화 | • (Efficiency) 메시지 6개, lookup 2회<br>• 메타데이터 (mem×comp) 엔트리 유지<br>• 1:1 고정 HW에서는 과설계 |
| **TRADEOFF 관계** | colspan → **낮은 dispatch overhead·예측 가능성 ↔ 리소스 활용도·유연성·확장성** | |

## 4. 슬라이드 산출

- 16:9, 표 1개가 슬라이드 본문을 채운다. 제목은 `DP<N>. <설계 질문>`.
- 실제 `.pptx` 파일이 필요하면 `pptx` 스킬로 생성한다. 표는 3열 × 5행(첫 열 = 항목명) + TRADEOFF 행 셀 병합.
- 대표 구조도는 텍스트 상자 + 화살표 도형으로 그린다. 이미지 캡처를 붙이지 않는다(폰트·해상도 불일치).
- 별점 매트릭스를 같은 페이지에 넣지 않는다. 필요하면 **다음 장**에 QA × 후보 별점 표를 따로 둔다.
