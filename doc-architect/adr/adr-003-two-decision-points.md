# ADR-003. DP1의 배치 결정 시점을 두 곳으로 둔다

| | |
|---|---|
| **상태** | Accepted — 이전 결정("배치 결정은 비활성 KV에만 실재한다")을 **대체한다** |
| **일자** | 2026-09-15 |
| **범위** | DP1 |
| **근거 문서** | DP1 설계 문서 §1 / DP1 구현 UML §0, §3.1 |

---

## 1. Context

이전 판은 **"갓 생성된 KV를 하위 계층에 두는 것은 순손실이므로 배치 결정은 비활성 KV에만 실재한다"** 고 서술했다. 결정점이 하나(비활성 전환)뿐이라는 뜻이다.

**그 결론은 연산 기능이 없는 계층만 고려한 것이었다.** [ADR-001](adr-001-prefill-gpu-pinning.md)에 따라 Decode Attention은 연산형 메모리로 보낼 수 있고, **연산형 메모리에 둔 KV는 되가져올 필요가 없다.** 따라서 활성 Decode 구간의 KV 위치도 실제 선택이 된다.

**Goals**

- 연산형 메모리를 활용할 수 있는 결정 지점을 설계에 드러낸다
- 두 지점의 **후보 집합과 입력 특성이 다르다**는 것을 구조로 표현한다

**Non-goals**

- Prefill 연산의 실행 위치 — ADR-001로 GPU 고정, 노드 선택은 DP2

**Assumptions**

- 연산형 메모리(Custom HBM 노드 · CXL-PNM)가 DP1 §4.4의 네 조건을 만족한다 — **구성 의존**이며 Pool에 해당 메모리가 없으면 결정점 A의 후보가 비어 있게 된다

## 2. Decision Drivers

| 순위 | Driver | 왜 중요한가 |
|---:|---|---|
| 1 | 설계의 완결성 | 실재하는 선택지를 설계가 갖고 있지 않으면 그 이득을 측정할 수 없다 |
| 2 | 비교 가능성 | 두 지점의 후보 집합이 다르므로 섞으면 어느 결정이 이득을 냈는지 분리되지 않는다 |
| 3 | 결정 비용 | 결정점 A는 Prefill 종료 직후이므로 여유가 결정점 B보다 적다 |

## 3. Options Considered

| 옵션 | 요약 | 장점 | 단점 | 되돌리기 |
|---|---|---|---|---|
| **A. 결정점 하나 (비활성 전환만)** | 이전 판 | 단순. 활성 경로에 결정 비용 없음 | **연산형 메모리의 이득을 구조가 담지 못한다.** 활성 Decode의 KV는 항상 HBM | 쉬움 |
| **B. 결정점 둘 (Prefill 종료 + 비활성 전환)** | 현행 | 두 이득을 모두 담는다. 후보 집합이 지점별로 명확 | 정책 훅이 둘. 결정 비용과 분기가 늘어난다 | 중간 |
| **C. 매 Decode step마다 재평가** | 연속 재배치 | 가장 적응적 | **활성 Critical Path 위에 결정 비용이 매 step 붙는다.** 이동 비용도 매 step 후보가 되어 진동 위험 | 어려움 |

## 4. Decision

**옵션 B를 선택한다. 결정점 A(Prefill 종료)와 결정점 B(비활성 전환) 두 곳에 정책 훅을 둔다.**

| | **결정점 A — Prefill 종료** | **결정점 B — 비활성 전환** |
|---|---|---|
| 질문 | 이번 턴의 Decode Attention을 어디서 수행할 것인가 | 유휴 구간 동안 KV를 어디에 보관할 것인가 |
| **후보** | **Decode Attention을 감당할 수 있는 메모리만** | **전체 6종** — 보관만 하면 되므로 |
| 주된 근거 | 예상 Decode 길이, 세션 KV 크기, 메모리의 Attention 수행 능력 | 재접근 시점·확률, 잔여 수명 |

- **후보 집합이 다르다는 것이 두 지점을 나누는 이유다.** 결정점 A에서 DRAM·HBF·SSD-PIM은 구조적으로 탈락한다 — 연산 기능이 없어 Decode 때 되가져와야 하므로 순손실이다.
- 옵션 C는 활성 경로 비용과 진동 위험 때문에 배제한다. **유휴 중 재조정은 직교 축**으로 분리해 별도 모듈에 둔다.

## 5. Architecture Impact

**경계와 계약**

- `DecisionPoint` enum이 `PREFILL_COMPLETE` / `DEACTIVATION` / `IDLE_REBALANCE`를 구분한다.
- **후보 필터링이 결정점에 따라 달라진다** — `FeasibilityFilter`가 `decision_point == PREFILL_COMPLETE`일 때 `MemorySpec.can_serve_decode_attention()`으로 후보를 좁힌다.
- **오프로드 가능 여부는 메모리가 정하지 정책이 정하지 않는다.** 정책이 직접 고르면 §4의 인과가 뒤집힌다.

**실패 모드**

| 실패 모드 | 조기 탐지 |
|---|---|
| Pool에 연산형 메모리가 없어 결정점 A가 무의미 | M-P7 오프로드 채택률 = 0 (정책의 실패가 아니라 Pool 구성의 귀결) |
| 결정점 A의 결정 비용이 Prefill→Decode 전환 지연을 키움 | M-P5를 결정점별로 분리 측정 |

## 6. Validation

- **M-P5(Placement Decision Latency)를 결정점별로 분리 보고한다.** 합치면 결정점 A의 비용이 결정점 B의 여유에 희석된다.
- **M-P7(오프로드 채택률)이 결정점 A의 존재 의의를 직접 측정한다.**

## 7. Consequences

**긍정** — 연산형 메모리의 이득이 설계에 표현되고 측정 가능해진다

**대가** — 정책 훅이 둘로 늘어 M-M1(결정 경로 복잡도)과 M-M4(분기 커버리지 비용)가 커진다. 옵션 A 대비 유지보수성의 대가를 지불하는 것

**측정 불가능해지는 것** — 옵션 C(연속 재평가)가 더 나았을 가능성은 본 설계로 답할 수 없다. 유휴 중 재조정 모듈이 그 일부를 대리한다

## 8. 재검토 트리거

| 트리거 | 무엇이 달라지는가 |
|---|---|
| Pool 구성에서 연산형 메모리가 빠지는 경우 | 결정점 A의 후보가 비어 옵션 A로 축퇴한다. 그 구성에서는 훅을 끄는 것이 맞다 |
| 결정점 A의 결정 비용(M-P5)이 이득을 상쇄 | 결정 주기를 낮추거나 결정점 A를 세션 단위로 캐싱 |
| 유휴 중 재조정의 이득이 큰 것으로 측정됨 | 옵션 C 방향의 재검토 근거가 된다 |
