# 메모: 품질 시나리오 정량 조건은 모든 DP를 본 뒤 하나의 규칙으로 통일한다

> 작성: 2026-10-09. 상태: 방침(사용자 결정 + Claude 의견). 수치는 아직 확정하지 않았다.

## 사용자 결정
1. DP1 문서의 Q-D 항목(임계값)은 **DP1만 보고 판단할 수 없다.** 모든 DP에 공통으로 적용할 값이므로 DP1~DP4(및 DP6)를 모두 훑어본 뒤 정한다. 지금 개별 확정을 요청하지 않는다.
2. 목표는 모든 DP의 QA 평가에 **수용 가능하고 일관된 구간**을 마련하는 것이다.
3. **심사위원은 절대 수치에 대한 판단을 하지 못한다.** 따라서 임계값은 심사위원이 절대값을 평가하지 않아도 납득할 수 있게 만들어야 한다.

## Claude 의견 (반영 방식)
- 절대값 자체를 설득하기보다 **임계값을 만든 규칙을 설득**하는 구조가 낫다. 심사위원이 검증할 수 있는 것은 (a) 규칙이 모든 DP에 똑같이 적용되었는가, (b) 값이 외부 근거에 묶여 있는가, (c) 경계를 움직이면 결론이 어떻게 바뀌는가(민감도)다.
- 외부 근거의 예: 공통 SLO(TTFT P99 ≤ 2 s, TPOT P99 ≤ 50 ms), Baseline끼리 비교해 측정한 잡음 대역, GPU 대수 환산, 문헌의 SLO와 달성률. DP1에서 이미 일부 쓰였다(`qa-criteria-dp1.md` §J).
- **주의: "모든 DP의 결과가 수용 가능하도록 구간을 마련"하는 것은 구간을 결과에 맞추는 것과 구별해야 한다.** 이전 평가에서 문제가 된 것이 결과를 본 뒤 경계를 정한 것(`defined_after_first_look`)이다. 임계값은 외부 근거와 일관된 규칙으로 정하고, 그 결과 어떤 DP의 일부 QA가 목표에 못 미치면 **그대로 미달로 보고**하고 보완 설계의 근거로 쓰는 것이 심사에서도 방어하기 쉽다. 평가 스킬 H5, H16과 같은 원칙이다.
- DP마다 고유한 지표(DP3 정확도 F1, DP2·DP4 Scaling Efficiency 등)는 같은 숫자를 쓸 수 없으므로 **같은 규칙으로 임계값을 도출**한다.

## 진행 순서
survey(DP2, DP3, DP4, DP6 문서 읽기와 요구사항 초안) → 통합(`consolidated.md`) → 임계값 제안(외부 근거 포함) → 사용자 확정 → 동결 → 재평가. 앞 단계에서는 임계값을 `[가정]` 후보 범위로만 적는다.
