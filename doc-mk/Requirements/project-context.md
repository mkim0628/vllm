# 과제 컨텍스트와 사용자 확정 사항 (요구사항 도출의 입력)

> 출처는 모두 `사용자`(대화에서 직접 확정). requirements-derivation 스킬 Phase 1/2의 공통 전제로 쓴다. 변경은 사용자 확정 후에만 한다.

## 1. 과제 정의
- 계층적 memory가 있는 시스템에서 메모리를 효율적으로 사용해 성능을 높이는 **런타임**을 개발한다.
- memory는 bandwidth/capacity가 다른 여러 메모리와 **PIM, PNM 같은 연산 가능 메모리**를 포함한다.
- 기존 메모리: HBM, DRAM, SSD (**실장 있음**).
- 차세대 메모리: HBF, ScHBM(Samsung Custom HBM), PIM, CXL-PNM (**시뮬레이션 연동이 타겟**).
- 이 연구는 **응용 레벨에 가까운 연구**다.

## 2. 시나리오 전제
| 항목 | 확정 내용 |
|---|---|
| 범위 | 단일 노드 + 멀티 노드 |
| HW | GPU 8장 서버 2대, 평가 SYS-H100 / SYS-B200 |
| 엔진 | vLLM 고정 |
| Actor | 시나리오에 따라 맞춤 (런타임 사용자/요청 클라이언트가 기본, 개발자 등은 시나리오별) |
| Workload | agent 중심. multi-turn, RAG, long-context, LoRA 멀티 테넌트, MoE 모두 포함 |
| 성격 | 정상 운전 중심. 당장 서비스가 목표 아님(이후 내부 활용 가능성) |
| FR | 외부에서 보이는 동작 수준. 우선순위는 Claude 제안 → 사용자 확정 |
| 성공 기준 | Claude가 시스템에 맞게 근거를 찾아 `[가정]`/`[B]`로 제안 |
| 산출 | md 먼저, FR/품질 속성/제약은 기본 PPT로 변환. 한국어 + 기술 용어 영어 |

## 3. 공통 제약 (사용자 확정)
| ID | 제약 | 유형 | 설계 영향 |
|---|---|---|---|
| GC-1 | 차세대 메모리(HBF, ScHBM, PIM, CXL-PNM)의 성능은 **시뮬레이션 기반 예상 성능**이다. 실측이 아니다 | 증거 한계 | 해당 메모리 관련 수치는 [C], 실측 [A] 주장 금지 |
| GC-2 | **device runtime의 오버헤드는 고려하지 않는다** (큰 제약) | 범위 밖 | 차세대 메모리 접근·연산 호출의 드라이버/런타임 지연은 모델에 없다. 실제 이득은 이보다 작을 수 있음을 한계로 명시 |
| GC-3 | device runtime에서의 **reliability, usability는 보장된다고 가정**한다 | 전제 | 장치 오류·API 사용성은 본 과제의 요구사항이 아니다 |
| GC-4 | 제품(메모리 장치) 자체의 **단위 테스트와 간단 응용 테스트는 완료**되었다고 가정한다 | 전제 | 장치 기능 검증은 범위 밖 |
| GC-5 | **device runtime 및 연산 가능 메모리를 지원하는 kernel/compiler 관련 runtime은 범위 밖**이다 | 범위 밖 | PIM/PNM 커널 구현·컴파일은 입력(주어진 능력)으로 취급, 연산 가능 여부와 성능은 profile 값으로 받는다 |
| GC-6 | 학습/훈련, 보안/테넌트 격리, 장애 복구는 범위 밖이다 | 범위 밖 | 요구사항에서 제외. LoRA 멀티 테넌트는 서빙 성능 관점만 다룬다 |
| GC-7 | 모델 정확도 불변(출력 bit-exact). **단 DP3(KV Drop)는 제외**이며 DP3는 정확도를 QA로 다룬다 | 전제 | DP0/1/2/4에서 손실형 압축·근사 적중 금지 |
| GC-8 | 차세대 메모리 관련 추가 제약은 사용자가 별도 글로 제공 예정 | 미정 | 수령 후 이 표에 합침 |
