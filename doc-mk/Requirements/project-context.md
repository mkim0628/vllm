## 0. DP 번호 체계 (사용자 확정 2026-10-09)

문서마다 번호가 달랐으므로 아래를 **최종**으로 쓴다. 폴더·파일 이름은 옛 번호를 유지하지만 이 문서군에서는 최종 번호로 쓴다.

| 최종 DP | 내용 | 옛 폴더/문서 |
|---|---|---|
| DP1 | **Migration 결정 구조** (evict, promote, **prefetch** 포함, 이기종 memory 사이 data 이동 결정) | `doc-mk/DP1/` |
| DP2 | Prefill/Decode **실행 위치 결정 구조** | `doc-mk/DP2/` |
| DP3 | **KV eviction 및 reuse** (long-context, 정확도와 교환되는 Drop 포함) | `doc-mk/DP3/` |
| DP4 | **요청 조율 계층 구조** (옛 DP0). 하위로 DP0-1(구조 결정: S1 중앙 결정형 대 S2 2단계 위임형)과 DP0-2(구현 방식: OSS 확장 대 직접 개발) | `doc-mk/DP4/`(커밋 05023c6에서 옛 `DP0/`를 이름 변경). `doc-mk/DP0-1/`은 아직 옛 이름 |
| DP6 | 옛 DP4: **비일관(non-coherent) CXL 공유 메모리에서 서버 간 KV 블록·메타데이터 일관성을 소프트웨어로 보장하는 구조**(C1 중앙 직렬화 대 C2 분산 락) | `doc-mk/DP6/`(커밋 05023c6에서 옛 `DP4/`를 이름 변경). `doc-mk/Evaluation/DP4/`는 아직 옛 DP4 평가 폴더 이름 |
| (DP5) | repo에 아직 없음. 사용자 확인 필요 | — |

옛 DP0는 최종 번호에서 DP4가 되었고 옛 DP4는 DP6이 되었다(사용자 확인 2026-10-09, repo 커밋 05023c6). "Agent tool-wait KV residency"는 DP1의 prefetch로 흡수했다. `GC-7`의 "DP3 제외"는 최종 번호에서도 그대로 DP3(KV eviction 및 reuse)이다.

## 1. 과제 정의
- 계층적 memory가 있는 시스템에서 메모리를 효율적으로 사용해 성능을 높이는 **런타임**을 개발한다.
- memory는 bandwidth/capacity가 다른 여러 메모리와 **PIM, PNM 같은 연산 가능 메모리**를 포함한다.
- 기존 메모리: HBM, DRAM, SSD (**실장 있음**).
- 차세대 메모리: HBF, ScHBM(Samsung Custom HBM), PIM, CXL-PNM (**시뮬레이션 연동이 타겟**).
- 이 연구는 **응용 레벨에 가까운 연구**다.

## 3. 공통 제약 (사용자 확정)
| ID | 제약 | 유형 | 설계 영향 |
|---|---|---|---|
| GC-1 | 차세대 메모리(HBF, ScHBM, PIM, CXL-PNM)의 성능은 **시뮬레이션 기반 예상 성능**이다. 실측이 아니다 | 증거 한계 | 해당 메모리 관련 수치는 [C], 실측 [A] 주장 금지 |
| GC-2 | **device runtime의 오버헤드는 고려하지 않는다** (큰 제약) | 범위 밖 | 차세대 메모리 접근·연산 호출의 드라이버/런타임 지연은 모델에 없다. 실제 이득은 이보다 작을 수 있음을 한계로 명시 |
| GC-3 | **device runtime 계층**의 reliability, availability는 보장된다고 가정한다 (장치 내부 오류 처리·장치 장애로부터의 복구는 범위 밖) | 전제 | 우리 런타임 계층의 degradation 처리(전송 실패 fallback, tier 용량·대역폭 저하 시 성능 저하 폭, 상태 신선도)는 **Reliability/Availability QA 후보로 열어 둔다**(제외 아님). 사용자 확정 시 선정 |
| GC-4 | 제품(메모리 장치) 자체의 **단위 테스트와 간단 응용 테스트는 완료**되었다고 가정한다 | 전제 | 장치 기능 검증은 범위 밖 |
| GC-5 | **device runtime 및 연산 가능 메모리를 지원하는 kernel/compiler 관련 runtime은 범위 밖**이다 | 범위 밖 | PIM/PNM 커널 구현·컴파일은 입력(주어진 능력)으로 취급, 연산 가능 여부와 성능은 profile 값으로 받는다 |
| GC-6 | 학습/훈련, 보안/테넌트 격리, 장애 복구는 범위 밖이다 | 범위 밖 | 요구사항에서 제외. LoRA 멀티 테넌트는 서빙 성능 관점만 다룬다 |
| GC-7 | 모델 정확도 불변(출력 bit-exact). **단 DP3(KV eviction 및 reuse의 Drop)는 제외**이며 DP3는 정확도를 QA로 다룬다 | 전제 | DP1/2/4에서 손실형 압축·근사 적중 금지 |
| GC-8 | 차세대 메모리 관련 추가 제약은 사용자가 별도 글로 제공 예정 | 미정 | 수령 후 이 표에 합침 |
| GC-9 | 서버 간 연결은 **PCIe 64GB/s**(실장 서버 2대). 차세대 메모리 기반 서버도 우선 PCIe 기반으로 가정한다. RDMA/NIC 종류는 미확인 | 환경 | 노드 간 KV 전송(DP4)의 대역폭 상한과 전송 vs 재계산 판단의 입력값. 이 값을 넘는 전송 이득을 요구사항으로 두지 않는다 |
| GC-10 | 문서·데이터 **갱신 시 KV 무효화(stale KV 처리)는 범위 밖**이다 | 범위 밖 | RAG 문서가 바뀐 경우의 KV 유효성 보장은 요구사항이 아니다 |
