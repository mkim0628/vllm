# DP2 후보 구조: 결정 주체·정보 범위 축의 A / B′ 비교와 보완 설계 C

> 작성: 2026-10-10. 상태: **초안(제안)**. 선행 문서: [`../Requirements/memo-dp2-redesign-ideation.md`](../Requirements/memo-dp2-redesign-ideation.md)(재설계 논의), [`../Requirements/memo-dp2-dp4-boundary.md`](../Requirements/memo-dp2-dp4-boundary.md)(DP2/DP4 경계). 기존 DP2 문서(`dp2-prefill-decode-execution-planning-decision-timing.md` 등)는 **수정하지 않았다**.
> 표기: **[사용자 결정]** / **[Claude 제안]** / **[추정]**(계산·추론, 미검증) / **[가설]**(평가로 확인할 예측) / **[문서 근거]**. 모든 수치 임계값은 통합 단계(`memo-threshold-unification.md`)에서 정하므로 이 문서에는 쓰지 않는다. 별점도 쓰지 않는다(정량 구간 미정의).
> 출처: 외부 AI가 제안한 두 구조(중앙 집중식 동기 오케스트레이터, 분산 자율 중개자)를 검토해 B를 B′로 재정의했고, 선택 후 보완 설계로 하이브리드 C를 둔다는 전략은 사용자 결정이다.

## 1. 결정 질문과 DP2의 위치

**결정 질문 [사용자 결정]**: Turn 시작 시, 한 노드 안에서 **KV 구간별 attention을 어디서 실행할 것인가**(P/D 구분 없음).

| 항목 | 내용 |
|---|---|
| 결정 단위 | **Turn 시작 시점 × (요청, KV 구간)**. 여기서 Turn은 **대화 턴(요청 단위)** 이며 디코드 step이 아니다 |
| 결정 값 `ExecTarget` | `GPU_STAGE`(KV를 HBM의 임시 staging 영역으로 옮겨 GPU attention) 또는 `IN_SITU(tier)`(KV가 있는 Tier에서 q를 받아 fused attention) |
| 범위 | 노드 내, attention 한정. 연산은 항상 GPU에서 시작(QKV 투영, FFN은 GPU) |
| 입력 | DP1이 정한 KV 배치(Tier별 위치). DP1은 DP1대로, DP2는 DP2대로 평가한다 |
| DP1/DP2 경계 | DP1 = 이동 후 데이터가 **남는** 배치, DP2 = 실행을 위한 **일시적 staging** |
| DP4와의 관계 | DP4는 이를 멀티 노드로 확장해 P 노드/D 노드를 분별한다(이 문서의 범위 밖) |

**공통 가정 [문서 근거 + 가정]**: 한 시퀀스의 KV가 여러 Tier에 걸치면 Tier별 부분 결과 `(m, l, o)`를 log-sum-exp로 병합한다. 부분 결과를 내는 kernel은 **주어진 것**으로 본다(GC-5, 확인 필요). 이 가정은 A, B′, C 모두에 공통이므로 후보 간 차이를 만들지 않는다.

## 2. 관련 QA와 제약

| ID | 내용 | 정의 |
|---|---|---|
| QA1 | Throughput | Max SLO Goodput. 지연은 SLO 조건으로 포함됨 |
| QA2 | Latency | TTFT·TPOT의 P99·P50. SLO와 달리 **꼬리 분포**를 본다 |
| QA3 | Resource Utilization | **HBM 점유율, 낮을수록 좋음**. QA1·QA2가 같을 때(iso-load, SLO 통과) KV·staging 점유를 비교. weight 제외 |
| 제외 | QA4(변경 용이성), QA5(확장성) | 사용자 결정. 신규 Tier는 Tier descriptor 추가로 처리하며, 노드 수 확장은 DP4 소관. 단 **결정 비용**은 QA1 sweep의 민감도(0.1/1/10 ms)로 남긴다 |

핵심 제약: C-A1 연산은 GPU에서 시작 · C-A2 iteration 단위 결정과 layer 스트리밍은 현실성이 없어 배제 · C-A3 연산 가능 메모리의 지원 연산은 attention 계열뿐(GC-5) · C-A4 모델 출력 불변(bit-exact) · C-A5 시뮬레이션 [B+C]이며 실측이 아님(GC-1).

## 3. 후보 도출: 왜 "결정 주체·정보 범위"가 축인가

| 후보 축 | 판단 |
|---|---|
| 결정 시점(C1 inline / C2 사전 계획) | 노드 내 + Turn 단위에서는 후보가 Tier 수 이하라 결정 비용이 무시할 만하다. C2의 존재 이유(결정 지연 은닉)가 사라져 C1이 항상 앞설 **가능성이 높다 [가설]**. 기존 평가에서도 C1/C2는 QA1에서 동점(954/956 tok/s)이었고 확장성(QA5)에서만 갈렸다 |
| 실행 방식(이동 후 GPU 연산 / 제자리 연산 / 분할-병합) | 결정의 **출력**이다. 결정 구조와 직교하므로 A, B′, C가 모두 이 값을 낸다 |
| iteration 경계 스케줄링, 배치 분할, layer 스트리밍 | **[사용자 결정]** 비현실적이라 기각(연산은 GPU에서 시작해야 함) |
| **결정 주체와 정보 범위** | **채택.** 전역 정보로 Cost를 예측해 중앙에서 정할 것인가, 로컬 측정 신호로 Tier가 분산해 정할 것인가. 후보 간에 QA가 실제로 갈릴 수 있다 |

## 4. 구조 A: 전역 Cost 기반 중앙 오케스트레이터

**개념**: 단일 Planner가 노드 내 모든 Tier의 상태와 링크 상태를 한 눈에 보고, Turn 시작 시 한 번에(single-pass) 모든 (요청, KV 구간)의 `ExecTarget`을 확정한다.

```
vLLM Scheduler ──(Turn 시작: 요청, KV 구간 목록)──▶ DP2 Planner (중앙)
                                                   ├─ Global State Table  (Tier 점유, 링크 잔여 BW, HBM 예산)
                                                   ├─ Cost Evaluator      argmin Cost(target)
                                                   └─ ExecutionPlan       [(req, seg) → GPU_STAGE | IN_SITU(tier)]
                          ┌────────────────────────────┴───────────────────────────┐
                          ▼                                                        ▼
                GPU Worker                                                Tier Worker (CXL-PNM, ScHBM)
                QKV 투영 → (GPU_STAGE 구간) staging 후 attention          q 수신 → fused attention → (m,l,o) 반환
                                  └──────────── LSE 병합 ◀──────────────────┘
```

- `Cost(target) = T_attn + T_rt + T_link + λ_HBM · ΔHBM점유`. `T_rt`는 IN_SITU의 layer당 q 송신·o 수신 왕복(80 layer 합) [추정: 구현 확인 필요], `λ_HBM`은 부하에 따라 달라지는 **HBM 기회비용 가격**(저부하 ≈ 0, 고부하 ↑).
- HBM 예산과 staging 허용은 Planner가 소유한다.
- **강점**: 전역 자원(링크, HBM)을 함께 최적화해 충돌을 줄인다. HBM 기회비용을 목적함수에 명시한다.
- **비용·약점**: ① **Cost Model 예측 오차에 의존**한다(DP2-C-1에서 정확도는 범위 밖, ε sweep으로만 다룸). ② Tier 연산 변동(jitter)이나 갑작스런 큐 적체를 Turn 중에 반영하지 못한다. ③ `λ_HBM` 보정이 필요하다.

## 5. 구조 B′: 로컬 신호·규칙 기반 분산 admission

> 원안(분산 자율 중개자)에서 **Shared Task Bus를 제거하고** 책임을 재정의했다. 이유: KV가 있는 Tier만 claim할 수 있어 Tier 간 경쟁이 없으므로 bus는 판단 로직 없이 hop만 늘린다. 실질은 "각 Tier가 자기 KV에 대한 접수/거절을 로컬에서 결정하는 분산 admission control"이다. [Claude 제안]

**개념**: 중앙은 Cost를 계산하지 않고 표준 Attention Task(`req, KV_descriptor, Deadline`)만 발행한다. 각 Tier의 **Tier Admission Agent**가 자기 KV에 대해 **로컬 측정 신호**(큐 깊이, in-situ 점유 시간, 링크 사용률)를 임계치와 비교해 접수(`IN_SITU`)하거나 거절(`GPU_STAGE` 폴백)한다. 폴백 staging은 **GPU 쪽 HBM Budget Admission**이 예산 안에서만 허용한다.

```
Thin Scheduler ──(Turn 시작: Attention Task)──▶ 각 Tier Admission Agent (CXL-PNM / ScHBM)
                                                   측정 신호(큐, 링크) ≤ 임계치 ? 접수 : 거절
                                       접수 ──▶ IN_SITU 실행, (m,l,o) 반환
                                       거절 ──▶ GPU HBM Budget Admission ──(예산 내)──▶ staging + GPU attention
                                                                             (예산 없음)──▶ 대기 또는 IN_SITU 강제
```

- 결정은 **Turn 시작 시점 1회**다. 원안의 "즉시 우회"는 디코드 중 전환을 뜻해 C-A2에 어긋나므로 제외했다.
- 우회 비대칭: 거절되면 GPU가 KV 전체를 옮겨야 한다(128K 컨텍스트 KV 약 43GB, PCIe 64 GB/s에서 약 0.67초 [추정]). 반대 방향은 q 송신뿐이므로 **거절 임계치에 hysteresis**가 필요하다.
- **강점**: ① Cost Model에 의존하지 않고 **측정값**으로 판단해 예측 오차와 jitter에 강건하다 [가설]. ② 중앙 결정 비용이 사실상 없다. ③ Tier별 책임이 분리된다.
- **비용·약점**: ① 로컬 신호만 보므로 전역 최적이 아니다. ② 동시 폴백 폭주로 링크 스파이크와 HBM 압박이 생길 수 있다. ③ Tier마다 임계치 보정이 필요하다. ④ HBM Budget Admission이 사실상 중앙 요소라 완전한 분산이 아니다.

## 6. A와 B′의 비교 (가설, 평가로 확인 전)

> 평가가 끝나기 전이므로 모두 **[가설]** 이다. 우열 표기는 "예상 방향"이며 점수가 아니다.

| 비교 | 구조 A | 구조 B′ | 근거 |
|---|---|---|---|
| 결정 주체 / 정보 | 중앙 / 전역 상태 + **예측** Cost | Tier 로컬 / **측정** 신호 + 규칙 | 설계 정의 |
| QA1 (고동시성 Goodput) | A 우세 예상 | 동시 폴백 폭주 시 열세 가능 | 전역 링크·HBM 조정 유무 |
| QA2 (꼬리) | Cost 오차·jitter가 크면 열세 | 측정 기반이라 강건할 수 있음. 단 Turn 시작 시 1회 결정이라 디코드 중 우회 이점은 없음 | 예측 대 측정 |
| QA3 (HBM 점유) | A 우세 예상 | HBM 예산 admission이 없으면 구조적 공백, 있으면 근접 | 소유자 유무 |
| 결정 비용 | µs~ms 수준일 것 [추정] (후보 ≤ Tier 수) | 거의 없음 | 노드 내 후보 수 |
| 의존하는 가정 | Cost Model 정확도, λ_HBM 보정 | Tier별 임계치 보정, hysteresis | 각 설계의 파라미터 |

**원안 비교표에서 제외한 항목**: "신규 Tier 확장성(QA4)에서 B 우위"는 QA4가 제외되었고 Cost Evaluator도 Tier descriptor 추가로 확장되므로 근거가 약하다. "스케줄러 오버헤드 A 높음"은 노드 내 후보 수가 작아 과장이다.

## 7. 선택 방법

최종 구조는 **평가 후 하나를 선택**한다. 사전에 정하는 선택 규칙:

1. 1순위 QA1(고동시성에서 Max SLO Goodput), 2순위 QA3(iso-load에서 HBM 점유), 3순위 QA2(꼬리). 임계값과 동률 판정은 통합 단계에서 정한다.
2. 아래 시나리오 전체에서 한 구조가 어떤 시나리오에서도 크게 지지 않을 때만 "우세"로 판정한다(시나리오별 승패를 보고).
3. 비교 변수는 하나만 바꾼다: 같은 시뮬레이터, 같은 DP1 배치, 같은 `ExecTarget` 출력, 같은 병합 가정.

| 시나리오 | 보려는 것 |
|---|---|
| 동시성 sweep (저→포화) | QA1 교차점(끌어오기가 불리해지는 부하), QA3 |
| Cost Model 오차 주입(ε = 0 / 0.2 / 0.4 / 0.6, 기존 평가 변수) | A의 예측 의존성 대 B′의 측정 강건성 |
| Tier 연산 jitter, 일시적 큐 적체 | QA2 꼬리, 판단 오류 영향 |
| 폭주 부하(동시 거절) | B′의 폴백 폭주, 링크·HBM 압박 |
| 긴 컨텍스트 세션 재개(64K~256K) | 우회 비대칭 비용, staging 경로 |
| 결정 비용 민감도(0.1/1/10 ms) | 결정 오버헤드의 QA1 영향 |

시뮬레이터 확장 필요 [추정, `sim-extension-scope.md` 미확인]: 현재는 Turn 단위 `(n_p, n_d)` 모델이며 staging과 연산이 순차(overlap 없음)로 가정되어 있다. KV 구간 단위 배치, Tier 큐 모델, 로컬 임계치 정책이 필요하다. HBM 풀 용량 제약(A08, A24)은 이미 모델링되어 있다. 고동시성에서 병목이 HBM 풀인지 `max_num_seqs=256`/token budget인지는 확인 필요.

## 8. 보완 설계: 하이브리드 C

선택된 구조(A 또는 B′)를 **기준 구조**로 두고, 평가에서 드러난 약점을 다른 쪽의 강점으로 보완한다. 기준이 A일 때의 C를 아래에 스케치한다(기준이 B′일 때는 중앙 Cost 계획을 "임계치 보정용 예측"으로 이식하는 방향이 된다).

| 구조 | 실패 양상 | 보완 가능한 쪽 |
|---|---|---|
| A | Cost 오차, Tier jitter, 큐 적체를 Turn 시작 시 못 봄 | B′의 **측정 기반 거부권** |
| B′ | 전역 HBM·링크를 못 봄, 폴백 폭주 | A의 **전역 예산·Cost 기반 계획** |

**C의 구조 [Claude 제안, 평가 전]**

```
Planner(A): Cost로 계획 P 생성 + 각 구간의 예측값(T_attn, 큐) 첨부
        │
        ▼ Turn 시작 직후, commit 전
Tier Veto Agent(B′ 요소): 측정 신호가 예측값의 (1+tol)을 넘으면 VETO(측정값) 반환
        │ VETO 있음
        ▼
Planner: VETO된 구간만 측정값을 반영해 1회 재계획 (최대 1 round)
        │ 재계획 실패 / 예산 없음
        ▼
GPU HBM Budget Admission: 예산 내 staging 허용, 아니면 IN_SITU 유지 또는 대기
```

- 결정 주체는 둘이지만 **권한을 분리**한다: 계획 생성은 Planner, 거부권은 Tier(거부만 가능, 다른 대상 지정 불가), 예산은 Planner·Admission이 소유.
- **루프 방지**: 재계획 1회, 이후 Turn 중 전환 없음(다음 Turn에 반영), 거절 임계치 hysteresis.
- 기존 C2의 Late Validation과의 관계: 이는 사전 계획이 아니라 **Tier 로컬 측정 기반 late validation**이다. 기존 설계 자산(hard/soft 조건, 백업 후보 → 재계획 → 기본 경로)을 재사용할 수 있다.
- 추가 비용: Tier마다 Veto Agent 1개, 피드백 경로 1개, Turn 시작 시 로컬 왕복 1회(결정 지연 증가).

**C 채택 조건**: 선택된 순수 구조 대비 **적어도 하나의 상위 QA에서 개선**되고 다른 QA를 악화시키지 않을 때만 채택한다. 개선이 크지 않으면 순수 구조를 유지한다(하이브리드가 항상 우월하다는 보장은 없다).

## 9. "왜 처음부터 C를 제안하지 않았나?"에 대한 근거

심사나 리뷰에서 예상되는 질문과 답변. **정직하게 말하면 A와 B′의 상보성 때문에 C 방향은 분석 단계에서 예견되었다.** 그럼에도 순수형을 먼저 평가하는 이유는 다음과 같다.

1. **효과의 귀속(ablation).** C는 A의 전역 Cost와 B′의 로컬 거부권을 합친 것이다. 처음부터 C만 설계하면 어느 요소가 어디서 효과를 냈는지 분리할 수 없다. 두 극단을 순수형으로 측정해야 각 요소의 **한계 기여**를 안다(예: ε가 커질 때 A가 얼마나 떨어지는가, B′의 동시 폴백이 얼마나 링크를 막는가).
2. **C의 설계 변수가 순수형 평가에서 나온다.** veto 임계(tol), hysteresis 폭, 재계획 횟수, 폴백 비용은 평가 전에는 근거 없는 숫자다. A/B′ 평가가 거부 빈도, 우회 비용, 상태 신선도 같은 파라미터를 제공한다.
3. **하이브리드는 복잡도와 책임 이중화 비용이 있다.** 결정 주체가 둘이면 plan 일관성(평가한 후보와 실제 실행의 일치)과 루프·진동 위험이 생긴다. 순수형의 한계가 **실증된 뒤에만** 이 비용이 정당화된다.
4. **기준선 확보.** A는 기존 C1에 대응해 기존 평가 자산(Cost 항, 외부효과 항, ε sweep)과 연결된다. B′는 새 변수(정보의 국소성)다. 순수형을 기준선으로 두어야 C의 개선이 무엇 대비인지 말할 수 있다.
5. **C가 항상 이긴다는 증거는 없다.** 하이브리드가 순수형보다 나쁜 영역(결합 비용이 이득을 넘는 영역)이 있을 수 있다. 그래서 C는 "선택 후 보완 설계"로 두고 **채택 조건(§8)** 을 둔다.

예상 반론과 대응:

| 반론 | 대응 |
|---|---|
| "처음부터 C를 알았으면 비교는 형식적이다" | 비교의 목적은 C의 **설계 변수와 요소별 기여를 얻는 측정**이다. 결과에 따라 C의 모양이 달라지거나 불필요하다는 결론이 나올 수 있다 |
| "B′는 A를 돋보이게 하는 허수아비다" | B′의 고유 가설(측정 기반 강건성)을 ε 주입, jitter 시나리오에서 검증한다. 원안의 근거가 약한 장점(QA4, 오버헤드)은 정직하게 제외했다 |
| "C가 복잡하기만 하고 이득이 작으면?" | §8의 채택 조건에 따라 순수 구조를 유지한다 |

## 10. 미결 질문과 위험

1. 평가 시나리오와 시뮬레이터 확장 범위(Tier 큐 모델, 로컬 임계치 정책)를 확정해야 한다.
2. `λ_HBM`(HBM 기회비용 가격)을 어떻게 정할 것인가(정적 상수 / 부하 비례 / 점유율 비례). A의 핵심 파라미터다.
3. 부분 결과 병합 kernel 지원 가정(GC-5)을 인정하는가. 인정하지 않으면 한 시퀀스의 KV는 한 곳에서만 실행해야 해 후보 공간이 줄어든다.
4. `T_rt`(layer당 q 송신·o 수신 왕복)가 IN_SITU의 TPOT를 지배할 가능성. 구현 방식(PCIe/CXL 왕복 지연)에 따라 결정이 크게 달라진다 [추정, 미검증].
5. 통합 단계에서 QA 임계값과 별점 구간이 정해지면 이 문서의 선택 규칙에 반영한다.
6. 노드 내 결정을 DP4(멀티 노드)로 확장할 때 노드 역할을 이 DP2의 후보 공간 제한으로 정식화하는 방안은 별도 논의한다(`memo-dp2-redesign-ideation.md` §4).
