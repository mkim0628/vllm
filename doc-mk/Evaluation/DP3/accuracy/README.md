# DP3 accuracy micro-benchmark: KV eviction, query-aware vs query-agnostic scoring

Status: measurement, Evidence [A] for this model/data/hardware only (real model forward passes on CPU), N=93.
Everything below is regenerated by the scripts in this folder; numbers are copied from `results/accuracy_summary.json`.

## Question
How much does SQuAD token-F1 drop relative to the full KV cache when context tokens are evicted at keep ratio r, if
importance is computed (a) from the actual question at request time (query-aware), or (b) ahead of time from a
representative query that is not the actual question (query-agnostic)?

## Reproduce
```bash
uv venv --python 3.12 $VENV
uv pip install --python $VENV/bin/python torch --index-url https://download.pytorch.org/whl/cpu
uv pip install --python $VENV/bin/python transformers datasets accelerate numpy
cd doc-mk/Evaluation/DP3/accuracy
$VENV/bin/python kv_evict_accuracy.py --n 150 --model Qwen/Qwen2.5-1.5B-Instruct \
    --ratios 0.5,0.3,0.2,0.1 --seed 0 --sanity 8 --time-budget-min 72   # resumable; this run stopped at N=93
$VENV/bin/python summarize.py        # writes results/accuracy_summary.json, prints the tables
```
Executed: torch 2.14.1+cpu, transformers 5.19.0, fp32, eager attention. Single uninterrupted run. `--n 150` was requested; the 72-minute budget stopped it after 93 examples (below the N>=150 goal,
above the N>=80 minimum).

## Setup
- Hardware: 4 vCPU Intel Xeon @ 2.1 GHz, 15 GB RAM, no GPU. Model `Qwen/Qwen2.5-1.5B-Instruct` (fp32).
- Data: SQuAD v1.1 validation (`rajpurkar/squad`). Target paragraph (must have >=2 distinct questions) + 5-7
  distractor paragraphs from other titles, shuffled (6-8 paragraphs; resampled until >=1200 tokens). Context
  1203-1764 tokens, mean 1381. One question per target paragraph, 93 distinct paragraphs. Seed 0.
- Prompt: Qwen chat format; `[system+instruction prefix][context][ "Question: ..." + "answer with a short phrase" ][assistant]`.
  Greedy decoding, <=32 new tokens, first line of the output is the prediction.
- Scoring: one full-KV prefill of prefix+context; then the scoring query (suffix) is run against the full KV with
  eager attention; score of context token j = attention received from the query tokens, averaged over all layers, all
  heads and all query tokens, then smoothed with an avg-pool (kernel 5). Same scorer code for all variants; only the
  query differs:
  - `aware`: the actual question. `repA`: "Summarize the key facts in the text." `repB`: a different question
  about the same paragraph (random other gold question of that paragraph). `repC`: a question from a paragraph whose title is
  not in the context. `random`: uniformly random tokens (control, one sample per example/r).
- Eviction: top-k tokens, **one kept set shared by all layers and heads** (not per-head). Always kept: the prompt
  prefix (system + instruction, ~40 tokens), first 4 and last 8 context tokens, all question/answer tokens. Budget
  = round(r x context tokens), counting the forced tokens. Kept tokens keep their original position ids (the cached
  keys already carry RoPE; new tokens get position ids continuing from the original length).
- Metric: SQuAD normalized token-F1 and exact match, max over gold answers. Relative drop = (F1_full - F1_cond)/F1_full.
  95% CI: paired bootstrap over examples, 2000 resamples (seed 0).

## Sanity checks (all passed)
- Keep-all (r=1.0) through the prune/index path reproduces the plain full-KV decode token-for-token: 93/93.
- Own decode loop (explicit position ids, external cache) equals HF `model.generate` on the un-cached sequence: 8/8.
  (Raw: `results/sanity_generate_check.jsonl`.)

## Reading
- Query-aware eviction loses nothing measurable on this task down to r=0.1: the point estimates are slightly *above*
  full KV (F1 0.74-0.76 vs 0.730), but the CIs of the drop include 0 for r<=0.3, and the r=0.5 CI barely excludes 0. The
  honest statement is "no detectable loss"; do not read it as a gain (likely mild distractor removal plus noise).
- Query-agnostic scoring is much worse. rep-A and rep-C are about as bad as each other and only modestly better than
  random at r>=0.3; at r=0.1 rep-C (0.270) is statistically indistinguishable from random (0.229) and rep-A (0.306)
  barely above it. Worst representative query: rep-C (query from a different context) at r=0.1 (+63.0% drop);
  rep-A and rep-C are within noise of each other at every r.
- rep-B (another question about the same paragraph) is the best query-agnostic variant: +5-7% drop at r=0.5/0.3
  (CIs include 0) and +16%/+27% at r=0.2/0.1; still clearly worse than query-aware at r<=0.2.
  Part of the rep-B benefit is that it points at the right *paragraph*, which is the main thing SQuAD needs; it is
  paragraph-level, not answer-level, relevance.
- Random control is the lower bound: +33% to +69% drop. Eviction without query information is damaging for this task.

## NOT tested
Selective recompute / re-prefill of evicted tokens, multi-context blending (chunk-wise KV concatenation / CacheBlend),
KV reuse across requests with different prefixes (all positions here are original; no position re-mapping needed),
contexts longer than ~1.8K tokens, models larger than 1.5B, other model families, quantized KV, per-head / per-layer
budgets (a single shared kept set was used), other tasks (multi-hop, summarization, code, long-form generation),
the decoding behavior beyond 32 new tokens, and any latency or memory measurement (this is accuracy only).

## Limitations
1. N=93 questions (target was 150): CIs are wide, especially for the small differences at r=0.5/0.3 (rep-B vs full,
   aware vs full). Single seed, single random-eviction sample per cell.
2. Single small model (1.5B, fp32) and single task (extractive QA with short answers). Extractive SQuAD is the most
   favorable case for attention-based eviction (the answer span is a copyable local span). The full-KV F1 of 0.730 is a
   zero-shot prompt result, not a tuned SQuAD number. Do not extrapolate to long-form generation or multi-hop reasoning.
3. Query-aware scoring here is an *upper bound* on what an online system gets: the scorer reads attention against the
   FULL KV (full prefill and a full-cache scoring pass for the question). A real online evictor that needs the pruned
   cache before the question arrives, or that cannot hold the full KV during scoring, would score worse. The
   comparison therefore measures information content of the query, not deployable end-to-end cost.
4. Scores are averaged over all layers/heads/query tokens, then one global kept set is used for every layer/head.
   Per-head budgets (SnapKV, AdaKV-style) would likely retain more at the same r. Smoothing (kernel 5) and the
   always-keep rules were fixed up front and not tuned per condition.
5. Distractor paragraphs are random SQuAD paragraphs from other titles, so paragraph-level discrimination is easy;
   in a real RAG pool, near-duplicate distractors would make both modes harder. rep-B being the same paragraph makes
   it an optimistic multi-query-reuse case; rep-A is one specific generic prompt, and other generic prompts were not tried.
6. rep-C uses one random foreign question per example; its result depends on that draw. The first sink tokens are the
   chat-template prefix, which is always kept; "first 4 context tokens" is a conservative extra.
7. Keep ratios apply to context tokens only; the always-kept prefix, 12 forced tokens and question/answer tokens mean
   the effective total KV retention is slightly above r (kept context tokens are recorded per row as `kept_ctx`).
8. Prediction = first output line; answers longer than 32 tokens would be truncated (rare with this prompt).
   Gold answers have spans of 1-N tokens; F1 is lenient on partial overlap.
9. CPU fp32 numerics: ties and greedy flips are possible but the r=1.0 and `generate` checks showed exact agreement.
