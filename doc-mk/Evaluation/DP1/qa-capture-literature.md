# QA1 달성률(capture ratio) 기준의 문헌 근거 — 사전 등록 (2026-10-04)

> 이 절은 문헌 수치를 모으기 **전에** 작성한 포함·집계 기준이다. 수치를 본 뒤 기준을 바꾸지 않는다. 바꾸면 변경 사유와 이전 기준을 아래 "변경 이력"에 적는다.

## 정의
- 달성률 = (후보 − Baseline) ÷ (Oracle − Baseline), 시나리오(쌍)마다. 개선 여지(Oracle/Baseline − 1)가 잡음(QA1 3.3%) 이하인 쌍은 "여지 없음"으로 집계에서 뺀다(목록에는 남김).
- Oracle = `Oracle-ideal`(`sim/policies.py`): C2 파이프라인에 **미래 접근률 완전 정보**와 **무비용·즉시 이동**을 준 정책. 증명된 최적이 아니라 근사 상한이다. 후보가 Oracle을 넘는 쌍은 별도 보고한다.
- 적용 범위: QA1(처리량). QA2는 Oracle이 지연 꼬리를 최적화하지 않아 후보가 Oracle을 넘는 쌍이 많아(6쌍) 상한으로 쓸 수 없다(진단으로만 보고). QA3는 Oracle이 HBM 절감과 무관해 적용하지 않는다.

## 문헌 포함 기준 (사전 등록)
1. 대상: 계층/이기종 메모리 또는 캐시에서 데이터 **배치·이동·캐싱·prefetch** 정책이 "oracle / optimal / ideal / Belady 대비 성능"을 **수치로** 보고한 연구. LLM 서빙(KV offload 등)을 우선하되, 이런 수치가 드문 경우 tiered memory와 캐시 교체 연구로 넓힌다.
2. 같은 종류의 성능(처리량, 적중률 기반 성능, 실행 시간 단축)을 oracle 대비 비율로 환산할 수 있어야 한다(원문 수치로 직접 계산 가능한 것만, 환산 과정을 적는다).
3. 출처는 URL과 함께 적고, 원문에서 확인하지 못한 수치는 쓰지 않는다.
4. 10개 내외. 제외한 후보와 사유도 함께 적는다.
5. 집계: 포함 문헌의 oracle 대비 달성률의 **중앙값과 범위**(사분위)를 보고한다. ★★★ 경계 x는 이 중앙값을 기본으로 하되, x가 모든 문헌에서 나올 필요는 없다(소유자 결정, 문헌 범위를 보고 정함). x의 선택 방법과 민감도(하위 사분위, 상위 사분위)를 함께 적는다.

### 제외한 후보와 사유
- Hawkeye(ISCA'16)·Glider(MICRO'19): OPT의 수치가 그림에만 있어 본문에서 이득 달성률을 계산할 수 없음(Hawkeye의 Mockingjay 표 수치는 #1에 포함).
- TMC(tiered memory 자원 배분): 최적 비용 대비 1.1~7.9%는 비용 지표라 성능 달성률과 다름.
- PARROT(ICML'20), HybridTier, Memtis, Nomad 등: oracle/optimal 대비 수치를 본문에서 확인하지 못함.
- 검색 결과 요약 문장은 신뢰하지 않았고, 위 표의 수치는 모두 원문에서 직접 확인했다. **10개에 못 미친다(수치로 쓸 수 있는 출처 5개, x 계산 2개 출처 4개 점).** 소유자 지시("10개 내외, x가 모든 문헌에서 나오지 않아도 됨")의 범위 안이지만 **LLM 서빙에 직접 해당하는 이득 달성률 문헌은 찾지 못했고 CPU 캐시와 tiered memory 문헌으로 대체했다.** 적용 가능성이 제한적임을 한계로 둔다.

### x의 결정
- 사전 등록한 규칙(중앙값)을 위 이득 달성률 점 {57%, 75%, 87%, 95%}에 적용: **중앙값 81% -> x = 80%** (반올림). 하위 사분위 약 70%, 상위 사분위 약 89%가 민감도 범위.
- **정의: QA1 ★★★ = Oracle-ideal 대비 이득 달성률(집계) ≥ 80%.** ★/★★ 경계는 기존 잡음 기준(Baseline 대비 처리량 비율 0.97)을 유지한다.
- 집계 방식은 시나리오 쌍별 평균이 아니라 **pooled(로그 이득의 합 비율)**를 쓴다. 이유: 문헌의 값(#1)은 벤치마크 평균 이득의 비율이라 이 방식과 같다. 이 선택은 두 방식의 값을 모두 계산한 뒤에 했다(`defined_after_first_look`): 평균 방식이면 C2는 0.75라 ★★이다. 어느 쪽이어도 선택은 바뀌지 않는다(아래).

### 우리 후보의 값 (H100+B200, 개선 여지 있는 10쌍, Oracle-ideal 대비; 재현: `sim/oracle_run.py --ideal`, `sim/capture_analysis.py --ideal`, `results/data/oracle/`)
| | C1 | C2 |
|---|---|---|
| pooled 달성률 | **0.62** | **0.83** |
| 쌍별 평균 / 중앙값 | 0.59 / 0.76 (1.0 초과는 1.0으로 자름) | 0.75 / 0.73 |
| H100 (4쌍) / B200 (6쌍) | 0.83 / 0.51 | 0.88 / 0.81 |
| 쌍 부트스트랩 95% 구간 | 0.33 ~ 0.87 | 0.70 ~ 0.93 |
| Oracle을 1% 넘게 넘은 쌍 | 0 | 1 (H100 `dyn_rag_shard_hotset_shift`, +3%, 잡음 수준) |
| QA1 별 (x = 80%, pooled) | ★★ | ★★★ |
| 현재 공식 QA1 별 (Baseline 대비 x1.30 경계) | ★★ (x1.298) | ★★★ (x1.422) |

- 두 정의에서 QA1 별이 같고 별 합계와 선택(C1 10 대 C2 9; 평균 방식이면 10 대 8)도 같다.
- **x 민감도 (pooled 기준):** x <= 0.62이면 C1도 ★★★, 0.62 < x <= 0.83이면 C1 ★★ / C2 ★★★, x > 0.83이면 둘 다 ★★. 문헌 점 {57, 75, 81(중앙값), 87, 95}%에 적용하면 57%에서는 둘 다 ★★★, 75%와 81%에서는 C2만 ★★★, 87%와 95%에서는 둘 다 ★★이다.
- 쌍 단위 부트스트랩 구간이 넓고 C1, C2 구간이 겹친다(10쌍뿐). **C2가 C1보다 달성률이 높다고 통계적으로 단정할 수 없다.**

### 한계
- **Oracle-ideal은 증명된 최적이 아니다.** C2 파이프라인에 완전한 미래 접근률과 무비용·즉시 이동을 준 휴리스틱이고, 후보가 1쌍에서 3% 넘겼다. 이동 비용을 포함한 Oracle(`Oracle-approx`)은 후보를 넘는 쌍이 많아(C1 3쌍, C2 5쌍) 상한으로 쓸 수 없어 보조 진단으로만 둔다.
- 개선 여지가 잡음(3.3%) 이하인 11쌍은 집계에서 제외했다(Common 시나리오 대부분: Baseline이 이미 포화).
- QA2의 Oracle 달성률은 Oracle이 지연 꼬리를 최적화하지 않아 후보가 Oracle을 넘는 쌍이 많아(6쌍) 별점에 쓰지 않는다. QA3(HBM 절감)는 Oracle이 정의되지 않아 적용하지 않았다. 둘은 기존 기준을 유지한다.
- 문헌은 CPU 캐시 교체와 tiered memory 연구이고 oracle의 정의, 지표, 워크로드가 우리와 다르다. #5(LLM KV)는 이동 비용 때문에 oracle prefetch도 이득이 없었다는 반증이며, 우리 시뮬레이터의 링크 간섭 결과(loop-log iteration 4)와 같은 방향이다.

## 갱신 (2026-10-04, 소유자 결정): QA2·QA3로 확장, 공식 별로 전환
- 소유자 지시로 QA1·QA2·QA3 별을 모두 이 기준(★★★ = Oracle 이득 달성률 >= 80%)으로 전환했다(`qa-criteria-dp1.md` §L). 위 "QA2는 Oracle이 지연 꼬리를 최적화하지 않아 상한으로 쓸 수 없다 / QA3는 적용하지 않는다"는 기술은 **`Oracle-ideal`을 QA2에 쓸 때의 결과**였고, 이를 대체하기 위해 `Oracle-lean`(무비용 즉시 이동 + 틱마다 접근된 객체만 HBM)을 QA2·QA3용으로 추가했다. 이 변경은 첫 시도의 결과(후보가 Oracle을 6쌍에서 넘음)를 본 뒤 한 것이다.
- QA2 달성률 C1 23%, C2 42%(개선 여지 19쌍), QA3 C1 3%, C2 -15%(14쌍). QA2/QA3의 Oracle은 QA1의 것보다 이상적이라 같은 x = 80%가 더 엄격하다(문헌 점수는 이 정도로 이상적인 상한에 대한 값이 아니다).
- 문헌 수집은 이 갱신에서 추가하지 않았다(출처 5개, 4개의 달성률 점 그대로).
