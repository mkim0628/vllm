## 0. 범위와 별 규칙

- 범위: **KV 캐시 관리만** (RAG·LoRA·MoE 제외). 압축은 범위 밖, DP3는 선택 재계산만 남음. 정확도 QA는 제외.
- 별: ☆(미충족) / ★1 / ★1.5 / ★2 / ★2.5 / ★3. **★1 = 품질 시나리오 요구값**(변경 용이성은 근거로 정함). ★1 초과는 0.5씩, 별 1·2·3개는 의미 있는 앵커에 두고 반 단계는 중점(log 지표는 기하 중점).
- 문헌 수치는 모두 "up to" 보고값이며 지표·baseline·workload·논문 버전이 달라 직접 비교가 아니다.

|---|---|---|---|

| Q3 | ★2 = 50%, ★3 = 75% | LMCache E2E 지연 50~75% 감소(사용자 인용). TTFT 한정 보고(AttentionStore 87~88%, Llumnix P99 TTFT 5.5x)는 TPOT가 섞인 r에서는 75%로 보수 설정 | AttentionStore·Llumnix 검색 요약. LMCache E2E는 사용자 인용 |
| Q4 | ★1 = 80% | Stakeholder 요구, AthenaK 65,536 GPU에서 80%(학습 workload) | 요구는 사용자 확정. AthenaK는 기존 문서에서 abstract 확인 |
| Q4 | ★2 = 90%, ★3 = 95% | 손실 10%/5% 이내(16노드에서 14.4/15.2노드분). USL: SE=1/(1+σ(N−1))로 σ 1.67%/0.74%/0.35% | **정책 선택**. 90% 관례의 인용 논문(arXiv 1704.03329)은 분자동역학 코드 생성 논문이라 출처에서 뺐다(기존 `qa-star-criteria-evidence.md` §4-1에도 같은 지적) |
| Q5 | ★1 = 5 module, 1.0 MM | module: 설계 component 12~14개 중 5개(36~42%). M/M: vLLM 최상위 KV connector 중앙값 356 LOC를 1개 신규 구현 ≈ 0.99 MM(공식 환산) = 1인 1개월 | LOC는 이 저장소에서 직접 계수. 공식·상수는 DP1 사전 등록(전부 ASSUMED) |
| Q5 | ★3 = 2 module, 0.5 MM | SWE-bench 평균 패치 1.7 file·32.8 line ≈ 0.32 MM(공식 환산), 0.5 MM = 1인 2주 sprint | SWE-bench 통계는 기존 문서에서 확인 |

Q5 공식: `M/M = [n × 3일 + L ÷ 40 LOC/일 × 2.0] ÷ 21`. 토큰 비용은 기준에서 제외했다. module 수 n이 M/M 안에 3일×n으로 들어 있어 두 지표는 독립이 아니다(n=2면 0.29 MM, n=5면 0.71 MM 선점).
변경 시나리오 3종: S1 새 메모리 tier, S2 이동·배치·재사용 정책 교체, S3 vLLM upstream 갱신 대응(데이터 객체 유형 추가는 범위에서 빠져 삭제).

## 2. 평가 시나리오: Agent KV Fleet

KV가 HBM을 넘고 재사용할 history가 있는 구간을 겨냥한 통합 시나리오(문헌이 이득을 보고한 조건과 같은 영역). **시뮬레이션 전 설계값**이다.

| 항목 | 값 | 계산·근거 |
|---|---|---|
| 모델·HW | Llama-3.1-70B BF16, 8-GPU 노드 (SYS-H100 / SYS-B200), DP2·DP4는 2~16 노드 | 기존 환경과 동일 |
| 세션 | 동시 agent 세션 256, 컨텍스트 평균 16K(8K→24K), 턴당 +1K, 출력 256, 세션당 10~20턴 | 16K KV = 327,680 B × 16,384 ≈ 5.0 GiB |
| tool 대기 | lognormal 중앙값 5 s (0.2~30 s sweep) | 유휴 비율 ≈ 50% [가정] |
| HBM 압박 | HBM KV 풀 ≈ 425 GiB(640×0.9 − 가중치 131 − 활성값 20) ≈ 85 세션분, 활성 KV 640 GiB = 풀의 1.5배 | Baseline은 preemption→recompute. 16K 재prefill ≈ 0.65 s vs DRAM→HBM 복원 ≈ 10~50 ms(이론) |
| 공유 KV | 세션 간 공유 문서 청크 30%, 그중 50%는 non-prefix 위치 | DP3 재사용·선택 재계산 조건 |
| 부하·SLO | 동시성 32→512 sweep, Q3는 Baseline Max goodput의 90% 고정. TTFT P99 ≤ 2 s, TPOT P99 ≤ 50 ms | |
| Baseline | vLLM 기본: HBM prefix cache + preemption recompute, KV 이동·노드 간 공유 없음, P/D 고정 | |

Phase: P1 정상 multi-turn(DP1) · P2 burst(DP2) · P3 공유 문서 wave(DP3) · P4 노드 확장 2→16(DP4, 별도 run) · 변경 시나리오(Q5). 별은 **이 regime에서의 조건부 별**로 읽는다.

- 출처: DP1 = `Evaluation/DP1` 결과(21쌍), DP2 = `Evaluation/DP2` 결과 §0.1(38쌍)과 `tools/unified_inputs.json`의 HBM, DP4 = `Evaluation/DP4` 결과 §0.1(CXL 공유 풀). DP3는 기존 시뮬(압축 기반 오프라인/온라인 후보)이 새 후보(Pipe-and-Filter / Shared Repository)와 달라 미측정.
- Q1~Q3 실측은 모두 ★1 기준(2x, 20%, 30%) 아래다. 중립 벤치마크는 HBM 압박과 재사용 history가 거의 없는 조건이기 때문이며, 새 시나리오가 그 조건을 만든다. **새 시나리오에서 구간에 도달하는지는 아직 모른다.**
- 방향이 소유자 별과 반대이거나 구분이 안 되는 곳: DP4 Q4(락 기반이 3, 실측은 N=16에서 두 안 동일 1.26), DP2 Q1(두 안 동일 ×1.66), DP2 Q3(2안이 더 나쁠 것으로 평가했으나 실측은 동일 수준), DP1 Q5(실측이 소유자 별보다 높음).
- DP4 Q4의 SE 1.26은 100%를 넘는 값이고, 기존 DP4 결과 문서도 이를 별 없는 제안 지표로만 보고했다. 기준 비교에는 제한적으로만 의미가 있다.
